# 微信助手（dsh-wechat-allsessions）

**v0.4.9 · DeepSeek Harness 微信 iLink 插件**

微信助手默认把 DSH **全部已有的未归档对话**与微信自动关联，新建对话也自动加入；每个对话默认开启广播。每条广播**最开头**固定显示会话 ID 和会话标题。插件设置页和微信命令都可独立开关指定对话的广播，重启后保留。

为兼容旧版数据，原 npm 包名、插件标识、配置命名空间、HTTP 接口前缀及 GitHub 仓库名称仍为 **dsh-wechat-allsessions**。**微信助手只是显示名称，不要将 Cordis ID 修改成中文。**

## 核心功能

### 0.4.9 匹配 DSH Desktop 原有管理员权限，修复真实重启失败

在 Windows 实机中发现：虽然 DSH Desktop 主进程运行于管理员令牌，旧版一次性重启任务却无条件按普通权限创建，导致可以启动执行器但不能完整结束 Desktop 进程树。新版只读核验**正在运行的 Desktop 根进程的实际 TokenElevation**，并使用完全相同权限级别创建一次性工作任务及 Desktop 启动任务；如无法安全确认目标权限，直接拒绝重启。不会弹 UAC、CMD 或 PowerShell 窗口，也不会给普通权限的 Desktop 不必要地提升权限。

同时，结束 Electron 子进程时仅忽略“检查时存在、操作时已经消失”的安全竞态；进程仍在却拒绝退出时必须报错停止，并以不含账号、路径和密钥的失败代码记录到重启状态。原有唯一主进程检查、旧进程清零、无临时任务、无额外轮询及微信重启回执门禁保持不变。

### 0.4.8 修复 Desktop 重启后的微信轮询启动失败

实机重启后曾出现 Desktop 新主进程和 Host 都正常、微信账号已加载，但消息轮询未启动，导致重启回执一直停留在 \`restarted\`。启动链中 \`notifyStart\` 网络调用失败会直接中断 \`pollLoop\` 初始化，这是可复现的结构性缺陷。现将启动通知作为尽力而为的操作；如果该通知发生瞬时网络/服务端失败，仍启动**唯一一套**原有 \`getUpdates\` 轮询，由既有错误重试机制恢复微信通道。只有 \`getUpdates\` 真正成功后才允许发送重启完成回执。不会额外运行监护程序、重复模型调用或多重消息轮询；停止状态下禁止重新启动轮询。

### 0.4.7 原生无控制台重启与双重清理

彻底移除 /restart 运行链上的 CMD/PowerShell 启动方式。插件随包携带一个 **Windows GUI 子系统（PE subsystem 2）原生辅助程序**，检查进程、创建一次性计划任务、校验清理均直接调用该程序，不会创建命令行控制台窗口。计划任务以当前用户交互令牌运行，不提权、不改变账号权限。

重启执行器不会把新 Desktop 当作自己的子进程启动。它先停止并核验旧 Desktop 的同安装路径进程树，然后由 Windows 任务计划程序**直接把原安装目录中的 DeepSeek Harness.exe 作为独立任务动作启动**。这避免短命执行器退出时把新 Desktop 一并终止。新 Desktop 任务使用无时间上限，防止任务计划程序在几分钟后误杀仍正常运行的应用。

资源清理分两层：正常情况下，新 Host 在微信连接和收发恢复后，删除工作任务、Desktop 启动任务及备用清理任务；若新 Host 未能正常启动，唯一的三分钟单次清理触发器会自行清除临时任务，不会周期重试。任务定义被删除不会终止正在运行的 Desktop；该行为已在 Windows 隔离环境验证。最终回执前必须确认旧 PID 全部消失、工作执行器退出、临时任务全部删除、当前仍是同一个新 Desktop 主进程。任何一项未通过都不发送成功通知。

重启流程不调用模型、不增加微信轮询、不留下常驻代理或监护进程。插件包包含辅助程序和可复现的 Windows 构建脚本 \`npm run build:restart-helper\`。


### 0.4.5 重启状态持久化及失败自动恢复

实际运行中发现 Windows PowerShell/.NET Framework 的 \`File.Replace\` 第三个参数不能为 null，否则重启监护程序可能已切换 Desktop，却无法写回“重启完成”状态。现改为使用非空备份路径原子替换，并在成功后清理备份文件。

重启进程树时，子进程有可能在检查与结束之间自行退出；现在能安全跳过已退出的进程。如 Desktop 已自行重新启动，不会重复启动第二个应用。新 Host 还能自动恢复“已重启但尚未回执”的有效请求：必须确认旧 PID 已退出、新 PID 为同一安装程序、微信通信恢复正常，才发送完成通知。

### 0.4.4 修复多级 Desktop 进程误判

原版只排除包含 \`--type=\` 的 Electron 子进程，但有的 DSH 正式版 Host/Node Worker 仍使用 \`DeepSeek Harness.exe\` 名称且没有该参数，导致将多个子进程误认为桌面主程序，微信 /restart 提示“无法安全定位”。现改成遍历同名 exe 的 PID/父 PID 关系，**只选择唯一的最上层根进程**，任何无根或多根不明情况仍拒绝动作。增加失败类别说明（主程序未运行、根进程不唯一、安装包不存在、重启状态读写失败、确认消息失败），不再把所有错误都错误归类为主进程找不到。

### 0.4.3 微信远程重启 DSH Desktop

微信发送 **/restart**，微信助手首先校验发送者必须是已绑定账号本人或显式受信任的用户，然后确认本机正在运行的 DeepSeek Harness Desktop 主进程。它先回复“正在重启”，把请求及回执目标持久化，随后调用随插件发行的 Windows 一次性重启监护程序。监护程序只针对独立、可确认的 Desktop 主进程，核实其安装包存在，停止旧 Desktop 主进程并启动**同一 exe**，等待新主进程出现。新 Host 加载微信助手后，会读取持久请求；确认已是不同的主进程 ID、账号和回信上下文可用，才会向微信发送“✅ DSH Desktop 已完成重启”。

**技术限制**：DSH Desktop v0.2.2-rc.3 的原生 app.relaunch() 入口仅属于 Electron 主进程；开发菜单由 !app.isPackaged 控制，正式安装版并未向 Host 插件开放此接口。微信助手不修改 DSH 官方安装文件，也不宣称调用了不存在的 IPC。0.4.3 当时使用的 PowerShell 重启驱动已在 0.4.7 移除，现由随包发行的 Windows GUI 子系统辅助程序负责重启。由于无法调用原生平滑重启入口，当前实现会**强制终止旧 Desktop 主进程**并启动原安装程序，而非正常 app.relaunch()，可能使运行中的任务或未保存内容中断，只应在需要时发送 /restart。

### 0.4.2 设置页自适应布局与账号移除

「连接状态与扫码」四项统计由固定横排改为窄宽度自动换行的网格，避免末尾「轮询」卡片溢出；账号条目、状态标签和操作按钮支持窄屏换行。「移除」按钮可解除任意微信账号在本插件内的绑定，操作前弹出确认，成功后立即刷新账号清单。对于当前正在收发的账号，会先停止长轮询，再从账号列表中移除；若仍有账号则预设第一个剩余账号作为下次启动的收发目标。移除最后一个账号后界面显示空列表，扫码仍可重新绑定。

注意：移除的是**微信助手本身的绑定记录**，不删除 DSH Host 的凭据，也不撤销微信服务端授权，以免破坏其他插件复用的登录态。账号记录使用串行化、独立临时文件及原子替换写入，移除失败保留原记录；移除当前账号后需重启 DSH Host 才能使回退账号生效。

### 0.4.1 完整句截断与续接命令保护

微信消息现在优先按**完整句子或完整行**组织发送，不会因为固定 1500 字节上限在一句话中间、/session 命令或会话 ID 中间硬切。正文超过 4000 字符时，在完整句末尾截断，明确标注后续正文已省略。消息数量上限不足时，仍保留最后一条完整的续接命令，并明确说明有内容未发送。单句、代码行或命令本身超过每条消息上限时，不发送不完整片段，改用截断提示，避免误导读者。

### 0.4.0 帮助排版及账号/会话清单核查

微信 /help 命令改为短句独立段落，微信端每个指令与说明独占一段；不再把多个指令挤在同一个连续文本块。

设置页拆分 **已保存微信账号数**、**实际长轮询账号数**、**DSH 服务可见会话数**，列出全部保存在本插件账号文件中的账号（不含令牌及用户 ID）。可指定一个收发账号，保存后重启 Host 生效；目前**只有一个账号可同时担任该插件的消息接收器**，另外已保存的账号不是在线状态，也不代表其他第三方插件的账号已接入。新扫码不会抹掉其他已保存账号。

会话服务返回的数组、Map、字典或分页列表现在采用统一读取逻辑；当数据为部分页面、未知格式，或服务未声明完整性时**不根据“本次没看到”归档其他会话**。设置页展示清单来源、每次返回条数及全量确认状态。此“会话数量”不是操作系统进程数，也不能把本机磁盘历史快照一概认作当前未归档对话。



### 0.3.1 专项修复：微信主动提问不回传

已验证旧 DSH Profile 可能仍安装 v0.1.0，并在 cordis.patch.yml 中将 enabled、broadcastAll、includeInternal 显式设为 false。**只更新 GitHub 仓库不会更新本机正在使用的插件**。需核对 Profile 的实际安装版本、启停配置与真正运行的 DSH 实例。新版收到微信 /help 会在助手内部直接回传帮助说明，绝不会转成提示词提交给“最新对话”。

微信主动发送普通消息后，通过会话 ID 绑定正确 DSH 对话；该回合完成的回答会按微信用户的上下文令牌回传。/status 新增 version、enabled、broadcastAll 与微信命令回传成功/失败记录（仅保留状态及原因，不写实际微信 ID、令牌和命令文本）。插件设置页显示正在运行的版本，以便发现安装/运行版本不一致。

**离线测试不等于真实运行环境验证。** 如果微信 /help 仍被写进 DSH 对话而不是由插件直接回复，说明当前微信消息入口并未正确启用最新版助手；要先定位真正接收消息的组件，避免两个 iLink 消费者同时读取同一个账号。


- **自动绑定**：启动读取 DSH 会话清单；监听 session/event，新会话无消息时仍每 15 秒巡检；归档对话自动排除广播。
- **自动广播**：新安装启用开关、全局广播开关默认均开启；每个会话的广播开关默认开启。历史上明确关闭过的配置保持不变。
- **清晰的消息头**：先显示“对话ID”“对话标题”，再显示本轮最终回复；末尾可选续接提示。
- **独立的回复路由**：微信发送 /session 选择一个对话来接收后续微信消息；其他会话广播不会覆盖此选择。
- **双端同步管理**：设置页按会话切换广播，微信 /broadcast on/off 也能切换；使用同一持久数据。
- **账号安全**：只有绑定所有者或明确授权的默认微信用户能读取会话、发送命令。微信上下文令牌仅按用户复用，旧 dsh-im 状态只读。
- **原有配置迁移**：原 sessions.json 中 v1 的 users 路由自动兼容新增的 v2 sessions 注册信息，旧回复绑定不丢失。

## 微信命令大全

| 微信消息 | 说明 |
|---|---|
| **/help** | 查看所有指令及使用说明 |
| **/list**、**/sessions** | 列出全部已登记、未归档的会话及广播状态 |
| **/session 会话ID** | 选择微信发来的普通文字所进入的 DSH 对话 |
| **/broadcast list** | 列出所有对话的广播开关 |
| **/broadcast off 会话ID** | 关闭该会话广播 |
| **/broadcast on 会话ID** | 开启该会话广播 |
| **/broadcast on**、**/broadcast off** | 操作当前已选择的会话 |
| **/broadcast status [会话ID]** | 查看指定（或当前）会话的广播状态 |
| **/clear**、**/new** | 清除微信回复目标；不删除 DSH 会话和广播设置 |
| **普通文字消息** | 提交到 /session 选择的会话 |

### 广播消息示意

~~~text
对话ID：session-abc
对话标题：墨界 Inkverse

本次开发任务已经完成，回归测试通过……

继续对话：/session session-abc
~~~

默认发送**新完成的最终文字回复**，不回填旧消息，不传输文件、图片、审批或工具执行过程。内部/定时和子代理完成的回复默认纳入，也可通过设置关闭；微信自己发起的对话回合完成时也会得到回复。

## 主要配置

| 字段 | 新安装默认值 | 含义 |
|---|---|---|
| **enabled** | true | 桥接启停，变更后需重启 Host |
| **broadcastAll** | true | 全局广播总开关 |
| **defaultUserId** | 空 | 留空使用绑定微信账号的 ownerUserId |
| **includeInternal** | true | 包含内部/定时及微信发起回合 |
| **includeSubagents** | true | 包含子代理回合 |
| **includeSessionHint** | true | 消息末尾带 /session 续聊命令；开头对话 ID、标题固定不隐藏 |
| **maxChunkBytes** | 1500 | 每段最多字节数，最多发送 20 段 |
| **routeStorePath** | 空 | 会话路由及广播开关文件路径覆盖值 |
| **accountConfigPath** | 空 | 微信账号配置文件路径覆盖值 |
| **statePath** | 空 | 微信状态文件根目录覆盖值 |

原有已持久化 enabled:false 或 broadcastAll:false 会得到尊重，**不会因升级被强行开启**。需要自动广播时，在设置页主动启用即可。未扫码的全新安装也会登记 DSH 对话，但账号连接前不会发送微信消息。

会话数据默认路径：**~/.dsh/integrations/dsh-wechat-allsessions/sessions.json**。请升级前备份。原 DSH 微信账号配置及 iLink 状态沿用原位置，本插件不会写回 dsh-im 的旧 state.json。

## 安装、升级和故障定位

请阅读 [安装与升级指南](docs/INSTALL.md)，并确保同一微信账号**不能有两个 iLink getUpdates 消费者**：运行微信助手时，要停用 dsh-im 内对应的微信接收通道，否则可能丢消息、重复消息。

在设置 → **微信助手** 可查看自动绑定清单与开关。若无法广播，请核对本机 **GET /plugins/dsh-wechat-allsessions/status**：

- **connected**：已加载微信绑定账号。
- **polling**：长轮询正在运行。
- **broadcastReady**：收件人的微信上下文令牌已就绪。若为 false，请用绑定的微信号向机器人发送一次 **/help**，让该用户的令牌建立后重试。
- **sendLog**：记录 no-account、no-context-token 等具体拒发原因。

广播列表与微信普通消息路由独立。微信 /session 选择目标后，其他会话完成广播不会抢走回复目标。

## 本机 HTTP 接口

原路径均保持不变（仅回环访问；POST 校验 Origin、限制请求体大小）：

| 路径后缀 | 方法 | 用途 |
|---|---|---|
| **/config** | GET / POST | 获取/保存全局设置 |
| **/status** | GET | 状态、账号、会话数、广播就绪度与发送日志 |
| **/sessions** | GET | 已绑定的未归档会话、会话 ID、标题、广播状态 |
| **/sessions** | POST | JSON 请求体为 sessionId 和 broadcastEnabled 布尔值，修改指定会话开关 |
| **/login** | POST | 新账号二维码与扫码登录状态 |

公共前缀为 **/plugins/dsh-wechat-allsessions**。
